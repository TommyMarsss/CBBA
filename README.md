# CBBA — 基于拍卖共识的多机器人任务分配

用 Go 标准库实现的 **Consensus-Based Bundle Algorithm (CBBA)** 多机器人任务分配模拟器，
支持竞价冲突仲裁、通信丢包模拟、收敛性检测，并生成单文件 HTML 回放报告。

## 快速开始

```bash
# 运行测试
go test ./cbba/ -v

# 运行一个随机场景并生成回放报告
go run ./cmd/cbba -robots 6 -tasks 14 -loss 0.3 -seed 42 -out report.html

# 在浏览器中打开回放
open report.html
```

CLI 参数：`-robots` / `-tasks`（规模）、`-loss`（单条消息丢失概率）、
`-seed`（场景与丢包的随机种子，可复现）、`-max-rounds`（轮数上限）、`-out`（输出文件）。

## 拍卖协议

每个机器人（agent）维护三份本地状态：

| 状态 | 含义 |
|------|------|
| `Y[j]` | 任务 j 当前已知的最高出价 |
| `Z[j]` | 任务 j 当前已知的赢家（机器人 ID，或 `-1` 表示无） |
| `S[m]` | 最近一次从机器人 m 直接或间接获得信息的时间（轮次） |

每一轮分三个阶段：

1. **竞价（bundle construction）**：机器人对每个未持有任务，计算把它插入当前执行路径
   每个位置的**边际收益**（时间折扣后的任务奖励 − 路径旅行成本），取最高者；
   只有边际收益**严格超过**当前已知赢家出价时才出价（平局按机器人 ID 小者优先，
   见 `beats()`）。出价即承诺：机器人把该任务加入自己的 bundle/path。
2. **共识（gossip consensus）**：机器人两两交换 `(Y, Z, S)` 快照，接收方按 CBBA
   规则表（`merge()`）逐任务合并：更新（update）、重置（reset）或保持（leave），
   并用时间戳向量 `S` 判断信息新旧。消息可能按给定概率丢失。
3. **释放（release）**：共识后，机器人丢弃那些已被别人赢走的任务
   （`Z[j] != 自己`）。**自己的承诺出价不重置**（见下文"已知局限"）。

### 冲突仲裁

两个机器人同时对同一任务出价时，规则是**全序且确定性的**：

1. 出价高者获胜；
2. 出价相同（误差 ≤ 1e-9）时，机器人 ID 小者获胜。

由于所有机器人用同一条规则合并同一份信息，最终必然对赢家达成一致——
不会出现两个机器人都认为自己赢了的分裂状态（由 `TestBidTieBreakByRobotID`、
`TestHigherBidWinsRegardlessOfID` 验证）。

## 收敛性保证

模拟器在以下三个条件同时满足时判定收敛（`Run()`）：

1. **静默**：连续 `quietRounds` 轮没有任何竞价、共识更新/重置或释放事件
   （消息丢失本身不算活动）；
2. **无冲突**：没有任何任务同时出现在两个机器人的 bundle 中；
3. **全局一致**：每个机器人的 `(Y, Z, S)` 状态都是两两合并的不动点——
   即任何可能送达的消息都不会再改变任何人的状态（`consistent()`，
   这是模拟器用于终止判定的中心化预言机，不影响分配本身）。

只要丢包率 < 100%（消息最终能送达），协议在有限轮内收敛到无冲突分配：
胜出出价单调不减（机器人只在出价更高时才竞价），任务换手次数有限，
陈旧信息最终会被更新的消息纠正。`TestConvergenceUnderPacketLoss`（50% 丢包）
和 `TestConvergenceAfterBlackout`（前 5 轮完全断网）验证了这一点。

## 无冲突性与完整性检测

`Validate()` 对最终结果做两项硬检查：

1. **无冲突**：任何任务不会被分配给多于一个机器人；
2. **完整性**：每个任务要么被唯一分配，要么被**显式报告为无法承接**
   （`UnassignableTask`，含原因与最优可能出价），绝不静默丢弃。

任务无法承接的两种典型原因：所有机器人都超出 `MaxRange` 航程；
或最优边际收益仍低于 `MinBid`（奖励不足以覆盖旅行成本）。

## HTML 回放报告

`RenderHTML()` 生成**单一自包含 HTML 文件**（数据与逻辑全部内嵌，
无第三方库、无外部请求、不启动服务），浏览器打开后可：

- 用播放/暂停、前后步进、滑块逐轮回放竞价与共识过程；
- 在场景地图上看到任务按当前归属机器人着色，冲突任务红色闪烁；
- 查看每轮事件流：出价（蓝）、共识更新（绿）、重置（紫）、
  级联释放（绿底）、消息丢失（橙）；
- 查看每个机器人当前 bundle 与最终分配汇总，以及无法承接任务的显式报告。

## 已知局限

1. **承诺式出价（committed bids）**：本实现中机器人一旦赢得任务就持有它，
   除非被更高出价击败——不会像原始 CBBA 论文那样在前置任务丢失时
   级联重置自己的出价。原因：当任务边际收益依赖路径且存在互补任务
   （一个任务让另一个"顺路"）时，级联重置会产生确定性活锁
   （两个机器人反复以路径相关的出价互相抢断）。承诺式语义保证
   胜出出价单调不减、必然收敛，代价是分配可能次优
   （机器人可能持有边际收益已变差的任务）。
2. **中心化收敛判定**：`consistent()` 不动点检查是模拟器层面的预言机，
   真实分布式系统需要额外的终止检测协议（如两轮全交换确认）。
3. **同步轮模型**：所有机器人按固定顺序竞价、同时交换快照；
   真实异步网络中消息延迟与乱序不在模型内。
4. **丢包模型**：每条有向消息独立同分布丢失，不模拟网络分区、
   延迟或带宽限制。
5. **任务模型**：任务不可拆分、无时间窗、无多机器人协作；
   路径顺序用贪心插入（非最优 TSP）。

## 项目结构

```
cbba/
  types.go      # 任务/机器人/事件/结果类型
  agent.go      # 机器人本地状态、竞价、共识合并、释放
  sim.go        # 轮次驱动、丢包、收敛判定、无法承接任务分析
  validate.go   # 无冲突性与完整性检查
  report.go     # 单文件 HTML 回放报告生成
  *_test.go     # 仲裁、丢包收敛、无法承接报告、大规模无冲突、确定性测试
cmd/cbba/
  main.go       # CLI：随机场景 → 报告
```
